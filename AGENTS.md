# AGENTS.md

## Project

datapact is an offline data-contract runtime. It parses an Open Data Contract Standard (ODCS) contract (YAML or JSON), lints the contract, and validates a CSV dataset against it. It runs locally, in the browser or in CI, with no warehouse connection and no upload. Output is human-readable text, stable JSON, or SARIF 2.1.0.

## Commands

- `bun install` — install dependencies.
- `bun test` — run the test suite in `tests/`.
- `bun run typecheck` — `tsc --noEmit`.
- `bun run build:site` — bundle `src/index.ts` into `site/assets/studio.js` (esbuild, IIFE, global `DataPact`).
- `bun run check:site` — validate every `site/*.html`.

## Layout

- `src/` — implementation. Must stay browser-safe: no `node:` imports and no Node-only globals.
- `src/cli.ts` — the `datapact` CLI entry point.
- `src/mcp.ts` — the MCP server entry point.
- `spec/` — the normative `SPEC.md` plus `example-contract.yaml` and `example-data.csv`.
- `tests/` — `bun test` files.
- `site/` — static pages and `site/assets/` (styles, self-hosted fonts, the generated browser bundle).
- `scripts/` — `build-site.mjs` and `check-site.mjs`.

## Conventions and hard rules

- `src/` must stay browser-safe: no `node:` imports and no Node-only globals, because it is bundled for the browser. Node-only code belongs in `src/cli.ts`.
- The site is fully static and offline: no external scripts or stylesheets, no network `src`, no telemetry.
- `site/assets/lens.css` is a shared design system copied byte-identical across the suite. Do not diverge it; per-tool changes go in `site/assets/theme.css`.
- `site/assets/studio.js` is generated by `scripts/build-site.mjs`. Edit `src/`, then rebuild; never hand-edit the bundle.
- `site/assets/fonts/*.woff2` are self-hosted Geist (SIL Open Font License 1.1). Do not swap them for a CDN.
- Every `site/*.html` must pass `bun run check:site`: exactly one `<h1>` and one `<main>`, a skip link whose `#fragment` matches an element id, and only classes defined in `lens.css` or `theme.css`.
- The `DP-*` rule codes are stable: lint `DP-101`–`DP-109`, validation `DP-201`–`DP-210`, suppression `DP-250`, and parse `DP-PARSE-000`. Do not renumber or reuse a code.
- The CLI contract is stable: `datapact check --contract <file> --data <csv> [--json] [--sarif <path>] [--fail-on <error|warning|info|none>]` and `datapact lint --contract <file> [--json]`. The exit codes are `0` (no findings at or above `--fail-on`), `1` (findings), `2` (invalid usage or parse error), and `3` (I/O error).
